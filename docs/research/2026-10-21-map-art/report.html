dg-village · map art research · 2026-10-21

라그나로크처럼, 도트 바닥 위에 소품을 세운다

dg-village 맵을 예쁘게 만드는 가장 현실적인 길은 라그나로크 온라인이 실제로 쓴 구조를 따르는 것이다. 바닥은 32px 도트 타일 텍스처를 입힌 저폴리 3D에 단차와 그림자를 주고, 나무·벤치·분수 같은 소품은 캐릭터와 똑같은 방식의 직립 도트 스프라이트로 세운다.

조사 4갈래(렌더링 방식, AI 도구·에셋, Unity URP 구현, 아트 디렉션)를 합친 보고서. 출처가 없는 계산·추론은 본문에 그렇게 표시했다.

요약
  • 방식: RO 하이브리드. 바닥과 건물 몸체는 3D + 32px 타일, 소품은 직립 스프라이트(32 PPU, Alpha Clip, X 35° 틸트) + 발밑 블롭 그림자.
  • 지금 바닥이 평평해 보이는 이유: 옥토패스 개발진이 겪은 "깊이감 부족"과 같다. 해법도 같다. 높이차, 빛과 그림자, 빈 바닥을 채우는 소품 밀도.
  • 먼저 고칠 것: 카메라 Ortho Size 5 → 5.625. 도트 크기가 정수배로 맞아떨어진다.
  • 도구: PixelLab이 1순위. 타일셋과 소품 모두 캐릭터와 같은 low top-down 시점과 고정 팔레트를 지원한다.
  • 첫 광장: 28×28유닛, 랜드마크 1 + 바닥 재질 2~3 + 소품 5~8 + 외곽 경계 + 조명. 두 주말.
01 · 방식 비교

네 가지 방식 중 RO 하이브리드가 1인 개발자에게 맞다

라그나로크는 같은 문제를 이미 풀었다. 바닥은 "32픽셀 텍스처 하나가 타일 하나"인 작은 반복 텍스처이고, 면마다 8×8px 저해상 라이트맵을 16단계로 포스터라이즈해 얹고, 타일별 버텍스 컬러로 반복 무늬를 깬다. 절벽은 이웃 타일 높이 차이에서 자동으로 생긴다 (GND spec). 그 흐릿하고 얼룩진 그림자가 손으로 그린 느낌을 만든다. 32px/타일은 dg-village의 32 PPU와 정확히 같다.

옥토패스(HD-2D) 개발진도 같은 교훈을 남겼다. 2D 아트에 조명만 더해서는 깊이감이 부족했고 3D 요소를 넣고서야 깊이가 생겼다. 해상도와 채도를 너무 올리면 도트의 매력이 사라졌고, 스프라이트가 "외로워 보여서" 타일 변형과 색 밀도를 늘렸다 (Nintendo Everything, Siliconera).

방식결과물 인상1인 제작 난이도캐릭터와 도트 일관성판정
(a) 3D 저폴리 + 도트 텍스처 (RO, HD-2D)깊이·그림자가 살아 있는 디오라마중간: ProBuilder 상자·평면 + 32px 타일좋음 (텍스처를 32텍셀/유닛으로 맞추면)바닥·건물에 채택
(b) 통짜 2D 그림/타일 배경가장 "한국 2D 온라인게임"답다가장 높음: 맵마다 한 장, AI 스타일 일관성 최악좋음기각
(c) 저해상 렌더 픽셀 퍼펙트 3D (A Short Hike, t3ssel8r)통일감 최고, 외곽선·밴드 조명가장 높음: render graph 커스텀 패스자동 통일, 대신 캐릭터도 리샘플됨나중에 실험
(d) 전부 직립 스프라이트 (Don't Starve류)AI 친화적, 건물이 평면적낮음: 전부 PNG최고소품에 채택

(c)는 결과가 가장 아름답게 통일되지만, 참고 사례들은 캐릭터도 3D 모델이다. 기존 64×64 스프라이트를 저해상 버퍼에 넣으면 정확히 맞추지 않는 한 픽셀이 먹히거나 두 배가 된다. 그래서 RO 하이브리드를 먼저 완성하고 (c)는 그 위에 얹는 후처리 실험으로 둔다. 같은 32텍셀 밀도로 만든 에셋은 640×360 버퍼에 그대로 들어맞으므로 지금 선택이 업그레이드 길을 막지 않는다(분석).

02 · 픽셀 규율

32텍셀/유닛 하나로 모든 픽셀을 묶는다

도트 맵이 싸 보이는 1순위 원인은 믹셀(mixels), 한 화면에 크기가 다른 픽셀이 섞이는 현상이다. 공들인 나무를 50% 축소하면 그 나무의 픽셀은 전경의 절반 크기가 된다. 작은 나무가 필요하면 작은 나무를 새로 그려야 한다 (wayline).

32 PPU모든 스프라이트. 캐릭터와 같은 importer 설정

카메라 배율 계산 (분석, 출처 없음)

Size 5 → 화면 세로 10유닛 → 720p에서 72 px/유닛 → 텍셀 1개 = 2.25 화면픽셀 (비정수: 걸을 때 반짝임)
Size 5.625 → 세로 11.25유닛 × 32 = 360텍셀 → 내부 해상도 640×360
720p ×2 · 1080p ×3 · 1440p ×4 (시야는 12.5% 넓어짐)

카메라가 35° 내려다보므로 바닥 텍스처는 화면에서 세로로 sin 35° ≈ 0.57배 눌린다. 세운 스프라이트는 눌리지 않는다. 라그나로크도 같은 현상이 있었고 플레이어들은 받아들였다(분석).

03 · Unity URP 구현

깊이 쓰는 컷아웃 + 블롭 그림자 + 3D 조명이 뼈대다

현재 설정(Universal 3D 렌더러, Alpha Clip, X 35° 고정 틸트)은 이미 올바른 기반이다. 스프라이트가 깊이를 쓰므로 "나무 뒤로 걸어가기"는 Sorting Group 없이 깊이 버퍼가 해결한다. 남는 문제는 기울어진 스프라이트 윗부분이 뒤쪽 벽을 파고드는 것 하나다.

  • 벽 파고듦: 첫 맵에서는 콜라이더로 캐릭터를 벽에서 1유닛쯤 떨어뜨린다. 제대로 고치려면 bgolus의 수직 빌보드 깊이 트릭을 손으로 짠 HLSL로 옮긴다. Shader Graph로는 깔끔하게 안 된다 (Unity Discussions).
  • 그림자: 실시간 섀도 대신 발밑 타원 블롭 섀도. 3D 건물·담장은 Directional Light 하나로 하드 섀도, 스프라이트는 그림자를 받기만.
  • 렌더러: Universal(3D) 유지. 2D Light는 메시에 안 먹히고, "Sort 3D As 2D"는 깊이와 3D 조명을 버린다. URP Pixel Perfect Camera도 2D 렌더러 전용으로 본다.
  • 조명: 노란 Directional 1개 + 푸른 Ambient + LUT 컬러 그레이딩 + 약한 비네트. 엔진이 hue-shift를 흉내 낸다.
  • 바닥: Terrain 말고 메시. 타일 데이터에서 메시 하나를 만드는 에디터 스크립트, 버텍스 컬러로 반복 깨기, ProBuilder로 연석·화단 단차.
  • 이동 제한: PlayerMovement에 콜라이더 스윕. 서버에도 같은 walkable 마스크를 두면 서버 권위 경계까지 얻는다.
버전 함정

Unity 6.4가 URP Compatibility Mode를 완전히 제거했다 (Unity 6.4 upgrade guide). RecordRenderGraph 없이 cmd.Blit을 쓰는 2019~2023년 픽셀화 튜토리얼과 레포는 6000.6에서 그대로 안 돈다. 참고용 Unity 6 + render graph MIT 레포: bababuyyy(640×360, 외곽선, 텍셀 스냅), schyro/PixelPipeline(Deferred+ 필요, WebGL 경고 신호).

WebGL2에는 컴퓨트 셰이더가 없다. VFX Graph 대신 Shuriken 파티클, 커스텀 패스는 실제 웹 빌드에서 검증.

04 · 도구와 라이선스

PixelLab이 1순위, Meshy/Tripo는 보조, 에셋팩은 라이선스부터

PixelLab 공개 API 스펙 기준: create-tileset은 16~25장짜리 Wang 타일셋을 만들고 view에 캐릭터와 같은 "low top-down"을 지정할 수 있다. 타일 32px, target_palette로 색 고정, lower_base_tile_id로 잔디→흙→돌길 연결. map-objects는 32~400px 투명 배경 소품을 만든다. 레퍼런스 이미지는 원본 해상도로 넣어야 한다. 스펙 스스로 "업스케일된 도트가 실망스러운 결과의 가장 흔한 원인"이라고 경고한다 (PixelLab OpenAPI).

원근이 두 번 걸리는 함정

low top-down 타일에는 원근이 그려져 있다. 바닥 타일은 평면에 깔아도 되지만, 벽이나 나무처럼 원근이 그려진 수직물을 바닥에 눕혀 깔면 35° 카메라 위에서 원근이 두 번 적용된다. 수직물은 반드시 세운 스프라이트나 3D 메시로 만든다(분석).

AI 에셋끼리 일관성은 같은 시점 프리셋, 같은 외곽선 규칙, 같은 target_palette, 고정 seed, 같은 32px로 얻는다. 타일셋은 가장자리가 어두워지는 이음매가 흔하다. 생성 직후 Unity 테스트 그리드에 4×4로 깔아 확인하는 습관이 필요하다.

05 · 아트 디렉션

예쁨은 명도 대비, hue-shift 팔레트, 둘러싸인 작은 광장에서 나온다

  • 가독성은 명도(value) 대비: 캐릭터가 "밝은 고채도 + 진한 외곽선"이니 맵은 반대로. 바닥은 외곽선 없이 중채도·중간 명도, 소품만 캐릭터와 같은 외곽선 규칙. 화면을 그레이스케일로 바꿔도 캐릭터가 읽혀야 한다 (wayline).
  • 팔레트: 밝아질수록 따뜻하게(스와치당 최대 약 20°), 채도는 램프 중간에서 최고. 최대 실수는 "고채도 + 고명도" (Slynyrd). girl01/boy01 색 추출 → 가까운 Lospec 팔레트(Resurrect 64, Endesga 64) → 맵용 저채도 서브셋 → 모든 생성의 target_palette.
  • 코지함: 안전·풍족·부드러움. 따뜻하고 대비 낮은 색, 자연 재질, 둘러싸인 공간. 깨는 요소는 "광막한 거리" (Game Developer).
  • 맵 크기: Gather 권장은 동시 접속자 1인당 20~40타일 (Gather Help). 30명이면 대략 25×25~35×35유닛(환산은 추론). 지금 20×20은 10~20명 규모. 화면 2~3개 분량이 적당하다.
  • 배치: 중앙 분수 + 둘레 모임 공간과 스폰, 2~6명용 대화 섬 3~4개, 가장자리 건물 입구(나중에 다른 채널 포털), 외곽은 낮은 담·수풀·물로 닫는다. 외곽을 막으면 코지함과 "바닥 밖으로 걸어 나감" 버그가 한 번에 해결된다.
